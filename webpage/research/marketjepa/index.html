MarketJEPA

A self-supervised world model that learns intraday market structure from the raw BQE universe, then trades the pretrained latent space.
This document describes exactly what happens while it trains — enough to rebuild it.

JEPA + SIGReg pretraining 7,659 stocks · 18.8 M sessions stock-agnostic by design resumable on an 8 GB GPU

What is MarketJEPA?

MarketJEPA is a from-scratch implementation of the Joint-Embedding Predictive Architecture (JEPA) — the self-supervised learning paradigm advocated by Yann LeCun — adapted to financial time series. It builds on the LeWorldModel recipe (JEPA paired with the SIGReg anti-collapse regularizer) and the masked-prediction idea from wav2vec 2.0.

The model is trained on the FirstRate split- and dividend-adjusted US equities dataset — roughly 7,659 stocks at 1-minute resolution since 2000. The data is stored in the BQE binary format, a domain-specific codec for 1-minute OHLCV described in its own paper, BQE-DeComp. MarketJEPA reads it in place, with no decompression to disk.

It has two halves. First, a self-supervised world model (Stage A) learns a latent-space representation of the stock market by predicting the future latents of price action — not raw prices, and deliberately not stock identities or calendar dates. This is pure representation learning: no labels, no returns, only an abstract embedding of what the market looks like and where it is heading. Second, a thin supervised layer (Stages B and C) — small classifier heads plus a decision policy — operates on the frozen latent and tries to generate alpha: estimating the probability and size of a profitable exit, timing entries and exits, and turning the representation into trades.

The thesis follows LeCun's world-model program: predict in a learned latent space rather than in raw price space, prevent representational collapse with one principled regularizer (SIGReg) instead of a stack of heuristics, pretrain once on the entire unlabeled universe, then attach cheap task-specific heads. A single strong pretrained latent then serves many downstream trading strategies at once. The full design specifications live in Papers/MarketJEPA_design_v3.md and Papers/TradingJEPASpace.md; this document describes the implementation's internals.

What this system is

Predict the future in a learned latent space; never memorise names or eras.

MarketJEPA is a three-stage pipeline that turns the BQE 1-minute equity universe into a tradeable signal. It follows the v3 design (Papers/MarketJEPA_design_v3.md) and the trading-readouts companion (Papers/TradingJEPASpace.md):

StageTrainsObjectiveCode
A — Pretrainingencoder fθ + predictor gφ multi-anchor, multi-horizon latent prediction + SIGReg anti-collapse training/trainer.py
B — Headssmall heads (backbone frozen) profitability term-structure, extremum/exit, forward return training/stage_b.py
C — Policythin rule layer receding-horizon optimal stopping policy/optimal_stopping.py
Core thesis. Pretrain on the full unlabeled universe by predicting future latents (JEPA), keep the representation from collapsing with a single regularizer (SIGReg), then attach thin supervised heads and a decision policy. The pretrained latent is the asset; everything downstream is a read-off from it.

The staged search (§12) is just coordinate descent over the fields of 𝒞; training/experiment.py is this tuple in code. The full menu for each axis is the design-space reference.

Two different "predictions" — keep them straight. Stage A predicts future latents (self-supervised, no labels). Stage B predicts whether an exit is profitable (supervised, needs realised PnL). They share the same chunk/anchor structure, which is what keeps the system coherent. Time (𝒯) is injected in Stage A, so every downstream stage inherits it.
Stock-agnostic, by design. The model is never told which ticker it is looking at. There is no per-stock embedding in the active configuration (cond_mode="time"), and absolute date/year is excluded from every feature. The model must learn transferable intraday patterns, not "NVDA goes up." This is what lets the same encoder serve all 7,659 names and generalise to unseen ones.

① Reading BQE — in place, no copy

The raw dataset stays in BQE format. BQEReader wraps the bqe Rust extension, which memory-maps each yearly file and decodes its independent row-bands across CPU cores. Decode is memory-bandwidth bound: warm throughput is ~200 M bars/s and is identical at 8/16/24 threads. Cold reads pay disk I/O, which read_many() overlaps across tickers with a thread pool (the GIL is released during decode).

RegimeThroughputMeaning
Warm decode (cache hot)~200 M bars/spure codec speed — 4.09 M AAPL bars in ~20 ms
Cold sequential~29 M bars/sfirst-touch disk I/O, not the codec
Cold parallel ×8~63 M bars/sread_many() overlaps disk seeks

Thread count is auto-tuned once per machine via BQE online calibration (start_online_calibration); the optimum persists to ~/.bqe_threads. On this box it settled on 8 threads.

② Preprocess → memory-mapped cache

Computing 12 pandas indicators per ticker costs 0.1–0.5 s. Doing that every training step for days would starve the GPU, so we compute features once and persist them. The cache is a derived artifact — much smaller than the raw minute data — and is what training memory-maps.

Shard layout (per ticker)

<cache>/manifest.json — τ, max_tokens(L), n_features, feature_names, n_chunks, year range
<cache>/vocab.json — deterministic ticker→id (sorted; stable across reruns)
<cache>/shards/TICKER.feat.npy — float16 [T_tok, 12] (winsorised ±30, memmap)
<cache>/shards/TICKER.close.npy — float32 [T_tok] (raw close, for labels)
<cache>/shards/TICKER.phase.npy — float16 [T_tok] (intraday phase u∈[0,1])
<cache>/shards/TICKER.meta.npz — offsets[n+1], weekday[n], dates[n], stock_id
<cache>/index/{o0,o1,wd,sid,tidx,dts}.npy — flat global session index (built once)

Sessions are stored contiguously (no padding wasted on disk); a session is the token slice feat[offsets[s] : offsets[s+1]]. Every write is atomic (*.tmp then os.replace), so a killed run never leaves a half shard — that is what makes preprocessing resumable (is_done() only sees complete shards; rerun the same command to finish stragglers).

③ Sharded dataset & batchloader

One sample = one (stock, trading-day) session. The dataset memory-maps the shards so only the rows of the requested session fault into RAM — 18.8 M sessions cost ~1 GB resident, not the full 32 GB.

How a session is sampled

The DataLoader shuffles the training subset, so each batch is random stock × random date: a 2001 KO session and a 2022 NVDA session can sit in the same batch. This is correct because (a) every sample is causally self-contained — features at bar t use only bars ≤ t — and (b) chronology is enforced only where it matters: the train/val boundary (next section). Mixing eras is intentional: with no absolute-date feature, the model cannot memorise a regime and is forced to learn relative structure.

Purged, embargoed temporal split (anti-leakage)

Validation = the most recent ~20 % of calendar days. Training = earlier days, minus a purge window (label horizon) before the val block and an embargo band after it. Because multi-horizon labels overlap and autocorrelate, a naive split inflates significance — this is the López-de-Prado purged CV the design mandates. Result on the full cache: train 11.79 M / val 7.02 M sessions.

Windows multiprocessing gotcha (fixed). DataLoader workers use spawn and pickle the dataset to each worker. Pickling the ~700 MB session index crashed with OSError: [Errno 22] / pickle data was truncated. Fix: persist the index to disk and memory-map it per worker (__getstate__ drops the memmaps). Side benefit: dataset startup dropped 85 s → 9 s.

The batch dict

# collate output — every tensor batched on axis 0 (B = batch size, L = max_tokens = 79)
{

The indicator formulas (§6)

Each token vector is built from three sub-axes: price fields, encodings (stackable), and indicator augmentations. The active set above is a minimal informative subset; the full menu and formulas:

# Encodings (all strictly causal, stackable):
log return        r_t   = log(c_t / c_{t-1})
delta             Δp_t  = p_t - p_{t-1}
norm-to-open      p̃_t  = p_t / o_session - 1
%prev-close       p̃_t  = p_t / c_prevclose - 1
rolling z-score   p̃_t  = (p_t - μ^w_t) / σ^w_t
rank-Gaussianise  p̃_t  = Φ⁻¹( rank_s(p_t) / (S_t + 1) )   # cross-sectional

# Parameterised Bollinger distance β(ℓ,κ,ω) — length ℓ, deviation κ, offset ω:
μ = (1/ℓ) Σ_{i=0..ℓ-1} c_{t-ω-i};   σ = std of same;   β_t = (c_t - μ) / (κσ + ε)

# RSI (length ℓ, Wilder smoothing):
Ū_t = (1-1/ℓ)Ū_{t-1} + (1/ℓ)·max(c_t-c_{t-1},0);   D̄_t analogous
RSI_t = 100 - 100 / (1 + Ū_t/D̄_t)

# EMA distance:
EMA_t = α·c_t + (1-α)·EMA_{t-1},  α = 2/(ℓ+1);   x_t = (c_t - EMA_t)/c_t

Other columns the design lists as worth testing: ATR, MACD, VWAP-distance, realised vol, order-flow imbalance. Ablation rule: add a channel only if it improves the cheap proxy metric (§12) beyond noise; prefer a minimal informative set (BB, z-score, EMA-distance are correlated). The cross-sectional rank-Gaussianise encoding is special — it makes a low-price and a high-price name directly comparable and makes the SIGReg Gaussian target natural.

⑤ Views, sessions & chunk/anchor structure

View (§4). The raw 1-min bars are clipped to regular hours (09:30–16:00) and resampled to timeframe τ (default 5min) with proper OHLCV aggregation (open=first, high=max, low=min, close=last, volume=sum). At 5 min a full session is ≤ L = 79 tokens; sessions are padded/truncated to L with a validity mask.

Intraday phase (§5). Each token gets u = position/(len−1) ∈ [0,1] — relative time only, reset every day. Never the absolute date.

Chunks & anchors (§8). The L tokens are partitioned into C = 6 equal contiguous chunks. A chunk latent z(k) is the masked mean of its tokens' encoder outputs. Every chunk boundary is an anchor from which the predictor rolls forward to all later chunks — so the representation must be forecast-useful at every time of day, matching the hourly re-decision deployment.

⑥ Time encoding & conditioning (stock-agnostic)

The only "side information" injected is relative time:

  • Time2Vec(u) — a learned linear term + sinusoids over intraday phase u∈[0,1]. The linear term captures monotone within-day drift (e.g. the close-auction ramp) and is safe because u resets every session; the sinusoids learn the periods that matter (open spike, lunch lull, close ramp) instead of us hard-coding "minute" and "hour". models/time_encoding.py. 
    t2v(u)[i] = ω₀·u + φ₀          (i = 0,  linear)
t2v(u)[i] = sin(ωᵢ·u + φᵢ)     (1 ≤ i ≤ K, learned frequencies)
  • Weekday embedding — a learned 5-row table (Mon–Fri); Friday→Monday is not a smooth cycle (weekend gap), so a learned embedding is the honest encoding, not a sinusoid.

Injection: the signal is projected by Wπ and added to every token embedding before the encoder — x̃_t = x_t + W_π·[ t2v(u_t) ‖ e_{w(t)} ]. Because the tokens are spaced by real elapsed time, this doubles as a resolution-aware positional signal (better than integer positions when mixing 1-min and daily tokens). A simpler baseline (raw sin/cos of minute-of-hour + hour-of-day) is kept for the ablation.

Explicitly excluded from every variant: date, day-of-month, week-of-year, month, quarter, year, and any unbounded time index. Absolute calendar time lets the model key on a specific era's regime, which destroys walk-forward generalisation.

This signal is projected and added to every token embedding before the encoder, and also summarised into the AdaLN conditioning vector. The conditioning axis (§9) is set to cond_mode="time":

cond_modeconditioning vector containsstatus
none—ablation
timetime signal onlyactive default — stock-agnostic
time+stocktime + per-stock embeddingablation only (name leakage)
fulltime + stock + (sector/index hook)ablation only
Why no stock embedding. A per-stock vector lets the model key on identity ("this is NVDA, which historically rose") — memorisation, not a tradeable pattern, and it fails to transfer to new tickers. Removing it also makes the latent space directly comparable across names, which is exactly what the cross-sectional strategies need.

⑦ Model architecture

Default: a hybrid backbone (CNN stem → Transformer), width d = 256, depth 6, 8 heads, dropout 0.1 — ~5.77 M parameters. The objective is backbone-agnostic; MLP / TCN / Transformer are drop-in alternatives (models/backbones.py).

Backbone families (§7) — the objective is backbone-agnostic

LeWorldModel showed JEPA+SIGReg works across ViT and ResNet, so encoder/predictor families are swappable while the loss stays fixed. All implemented in models/backbones.py:

Width d ∈ {256, 768, 1024} — d saturates past a threshold (LeWM observed ~184), so tune it by probing rather than assuming bigger is better.

⑧ The forward pass — exact shapes

For one batch (B sessions, L=79 tokens, d=256, C=6 chunks):

x  = input_proj(features)            # [B,79,12] -> [B,79,256]
x  = x + time_proj(t2v(phase) ‖ weekday_emb)   # inject relative time
a  = cond(time_raw)                  # [B,128]  AdaLN conditioning (NO stock id)
z  = encoder(x, a, valid)            # [B,79,256] per-token latents (causal)
zc, cv = pool_chunks(z, chunk_ids, valid, C)   # [B,6,256], [B,6] valid mask
pred = rollout(zc, a)               # [B,6,6,256]  pred[:,k,j] = forecast of chunk j from anchor k
proj = bn_head(zc)                  # [6,B,256]  per-chunk SIGReg embeddings

The rollout is autoregressive in chunk space: from the true anchor latent z(k) it predicts z(k+1), then feeds its own prediction forward to z(k+2) … z(C). Only entries with j > k are used.

⑨ The loss: multi-horizon JEPA + SIGReg

Multi-anchor, multi-horizon prediction (§8)

Lmulti = (1/Z) Σk=1..C-1 Σj=k+1..C γj-k ‖ ẑ(j|k) − z(j) ‖²

Mean-squared error between each rolled-forward prediction and the true later chunk latent, discounted by horizon (γ = 0.85; far horizons compound error). Pairs touching an invalid chunk are masked. Per-horizon MSE is logged separately — it should rise with horizon (the skill-decay curve). No stop-gradient on the targets.

SIGReg — the anti-collapse spine (Appendix A, implemented exactly)

Without a regularizer, predicting your own latents collapses them to a constant. SIGReg pushes the per-chunk embedding distribution toward an isotropic Gaussian 𝒩(0,I) using 1-D normality tests along random projections (Cramér–Wold). For each chunk index, on the BatchNorm-projected embeddings Z ∈ ℝB×d:

# resample M=1024 random unit directions every step
g ~ N(0,I_d);  u = g/‖g‖;  h = Z·u            # [B, M]  projections
A(ν)=mean_n cos(ν·h_n);  S(ν)=mean_n sin(ν·h_n)   # empirical char. fn
φ0(ν)=exp(-ν²/2)                                # standard-normal target
T = 2 Σ_q Δ_q·w(ν_q)·[(A-φ0)² + S²]            # Epps–Pulley, trapezoid on [0.2,4], Q=17
SIGReg = mean over directions, then over chunk indices

Every term is differentiable through h = Z·u, so gradients flow with no stop-gradient. verify.py asserts SIGReg ≈ 0 on a true Gaussian, large on a collapsed batch, and finite-gradient. Total: LA = Lmulti + λ·SIGReg, λ = 0.1 — λ is the one sensitive knob; raise it if effective rank falls.

⑬ Stage B — supervised heads

On the frozen backbone (or lightly fine-tuned), small heads are trained on hindsight labels (training/labels.py, models/heads.py). All operate on the contextual embedding ct at a decision point.

# 10.1 Profitability term structure — one head answers ALL horizons via φ_{j-k}
P̂(k→j) = σ( MLP_P(c_{t_k}, φ_{j-k}) )        # prob. of a profitable exit
r̂(k→j) =    MLP_r(c_{t_k}, φ_{j-k})          # expected return (+ a variance head for risk)
label   y(k→j) = 1[ (c_{t_j} - c_{t_k}) / c_{t_k} > τ_cost ]    # long side
# {r̂(k→j)}_{j>k} is the model's forecast curve from "now".

# 10.2 Real-time extremum / exit-timing — nowcast, not a forecast
ŷHI_t = P( c_t = max c | F_t ),   ŷLO_t = P( c_t = min c | F_t )
# exact extrema are sparse -> focal loss and/or a soft proximity target:
ỹHI_t = exp( -(c_t - max c)² / (2δ²) )
# or the smoother continuous framing — remaining intraday move:
m_t = log(c_N / c_t)            # ≤0 near the top, ≥0 near the bottom

# 10.3 Forward-return regression (auxiliary), h ∈ {5,15,60}
μ̂ʰ_t = wₕᵀ c_t ≈ E[ log(c_{t+h}/c_t) | F_t ]

# 10.4 Losses
focal:  L = -Σ [ y(1-ŷ)^ζ log ŷ + (1-y) ŷ^ζ log(1-ŷ) ],  ζ = 2
returns: Huber
Select on validation Sharpe, not accuracy. Under this extreme class imbalance accuracy is meaningless; a 50.1%-chance-of-tiny-gain signal is worthless after costs, which is why the term-structure head also emits a variance/quantile output for risk.

⑭ Stage C — optimal-stopping policy

Decisions are re-made at each chunk close (receding horizon). For an open long entered at chunk e, price pe, closing now pays gk = (ctk − pe)/pe − cost. The hold/close choice is an optimal-stopping problem with value

V_k = max( g_k ,  E[ V_{k+1} | F_{t_k} ] − ρ·Risk_k )

The practical greedy rule uses the §10.1 forecast curve directly (policy/optimal_stopping.py):

# flat -> enter if best risk-adjusted forecast clears a threshold
ENTER  iff  max_j ( r̂(k→j) − cost )  >  entry_threshold
# long -> hold if the best future risk-adjusted return beats closing now
HOLD   iff  max_{j>k} ( r̂(e→j) − cost ) − ρ·Var̂  >  g_k

then re-evaluate at the next chunk. Equivalently one can run LeWM-style CEM/MPC rollouts in latent space and pick the exit time minimising cost — the head is the fast learned version of that planning step. The extremum head (§10.2) is the special case "the best exit is now." Position sizing: fixed-fractional risk with broker volume-limit clamping, stop distance in price units.

Search strategy (§12 — do not grid-search everything)

Staged, proxy-driven coordinate descent over axis groups, in this order:

  1. Fix a reasonable backbone (CNN-stem → small Transformer) + pure multi-horizon JEPA.
  2. Search input/features/time first (𝒱, ℱ, 𝒯) — where the alpha most plausibly lives.
  3. Freeze those; search architecture 𝒜 and sizing.
  4. Freeze 𝒜; tune objective 𝒪 (masking, γ, λ, optional quantizer) and heads ℋ.
  5. Only then run full cost-aware walk-forward backtests on finalists.

Fast proxy metrics rank configs on the frozen representation before any backtest: linear-probe forward-return Pearson r and probe MSE; SIGReg health (smooth early drop then plateau; effective rank not collapsing); extremum / term-structure AUC. Use random search → Bayesian optimisation / successive halving over the discrete axes, and log every config + metric so the matrix becomes an analysable dataset.

Evaluation methodology (§13)

13.1 Representation probing (before any backtest)

Linear and MLP probes recover realised vol, forward-return sign, trend, and VWAP distance from the frozen latent; report MSE and Pearson r against raw-feature, PCA, and from-scratch-supervised baselines. strategies/panel.fit_return_probe is the forward-return probe.

13.2 Horizon-skill & calibration ("how well does it predict the future")

  • Calibration: reliability curve + Brier score Brier(Δ)=mean(P̂−y)² — when the head says 70%, does it happen ~70%? Recalibrate (temperature / isotonic) walk-forward.
  • Skill-decay curve skill(Δ): AUC / return-correlation vs horizon. This curve is the test of "maybe only the next hour is reliable" — if skill collapses past Δ=1 the policy correctly becomes near-horizon with frequent re-evaluation.

13.3 Anti-collapse diagnostics

Effective rank, per-dim variance, and the SIGReg value over training — smooth, unlike a noisy multi-term VICReg objective. training/metrics.py; logged every validation.

13.4 Surprise detector (violation-of-expectation)

Surpriset = ‖ẑt−zt‖² spikes on genuine structural breaks (gaps, halts, flash crashes) → a risk-off / flatten trigger and regime flag; shippable as a standalone monitor independent of any trading signal.

13.5 Trading backtest

Strict temporal walk-forward; full costs (spread, slippage, borrow); net Sharpe / Sortino / max-DD / turnover / capacity; ablated vs no-pretraining, an indicator baseline, and a random-entry control.

Optional module — discrete regime tokens (VQ) (Appendix B)

Status: optional, not in the default objective. Use only if you want interpretable discrete "market regime" codes, codeword features for the surprise/regime detector, or a contrastive baseline to benchmark against JEPA+SIGReg. It adds a codebook-collapse failure mode that the diversity loss exists to prevent.
# Product quantization with straight-through Gumbel-softmax (G groups × V entries)
p_{g,v} = softmax_v( (ℓ_{g,v} + n_v)/τ ),   n = -log(-log u),  u~U(0,1)
# forward = hard argmax; backward = soft p. Concatenate chosen entries -> project to q.

# Contrastive loss (replaces/supplements MSE) — true target q_t among K distractors
L_m = -log [ exp(sim(c_t,q_t)/κ) / Σ_{q̃∈Q_t} exp(sim(c_t,q̃)/κ) ]

# Diversity loss prevents codebook collapse (p̄_g = batch-avg softmax, no Gumbel)
L_d = (1/GV) Σ_g Σ_v  p̄_{g,v} log p̄_{g,v}
# Combined: L = L_m + α·L_d (+ optional λ·SIGReg).  Typical: G=2, V=320, κ=0.1, α=0.1

# 0. correctness gate (always run first)
python scripts/verify.py

# 1. preprocess once (resumable; rerun to finish stragglers)
python scripts/preprocess.py --all --start 2000 --end 2026 --workers 8 --cache cache/prod

# 2. pretrain Stage A (resumable: rerun the SAME command to continue)
python scripts/pretrain.py --cache cache/prod --ckpt-dir checkpoints/stage_a \
    --backbone hybrid --cond-mode time --dim 256 --batch-size 256 \
    --max-steps 400000 --warmup 2000 --ckpt-every 1000 --val-every 2000 --workers 4

# 3. watch the edge develop
python scripts/monitor_eval.py --cache cache/prod --ckpt checkpoints/stage_a/latest.pt --interval 900

# 4. pick the best trading model
python scripts/run_strategies.py --cache cache/prod --ckpt checkpoints/stage_a/best.pt
